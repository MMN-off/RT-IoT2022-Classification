# RT-IoT2022 Network Attack Classification

A multiclass machine-learning project that classifies IoT network traffic records using the **RT-IoT2022** dataset. The project compares five classifiers and includes a Streamlit application for evaluating saved models on a labelled test CSV.

**GitHub repository:** https://github.com/MMN-off/RT-IoT2022-Classification  
**Live Streamlit application:** To be added after deployment on Streamlit Community Cloud.

## 1. Problem statement

Internet of Things (IoT) environments contain many connected devices and can be exposed to different forms of malicious network activity. The aim of this project is to build and compare multiclass classification models that use network-flow features to identify the traffic category recorded in the `Attack_type` target column.

The work covers dataset exploration and preparation, model training, evaluation on a held-out test set, saving the trained preprocessing/model pipelines, and using those saved pipelines in an interactive Streamlit application.

## 2. Dataset description

- **Dataset:** RT-IoT2022
- **Source:** [UCI Machine Learning Repository – RT-IoT2022](https://archive.ics.uci.edu/dataset/942/rt-iot2022)
- **Dataset citation:** B. S. and R. Nagapadma (2023). *RT-IoT2022*. UCI Machine Learning Repository. https://doi.org/10.24432/C5P338.
- **Original records:** 123,117
- **Target column:** `Attack_type`
- **Task:** Multiclass classification with 12 target classes
- **Target classes in the supplied CSV:** `DOS_SYN_Hping`, `Thing_Speak`, `ARP_poisioning`, `MQTT_Publish`, `NMAP_UDP_SCAN`, `NMAP_XMAS_TREE_SCAN`, `NMAP_OS_DETECTION`, `NMAP_TCP_scan`, `DDOS_Slowloris`, `Wipro_bulb`, `Metasploit_Brute_Force_SSH`, and `NMAP_FIN_SCAN`.

The dataset represents IoT network traffic and contains both normal/device-related activity and attack traffic. It includes flow-level numeric measurements and categorical protocol/service fields.

### Data preparation

The supplied CSV was inspected before model training. The preparation steps used for the modelling dataset included:

1. Removing the `Unnamed: 0` index-like column because it is not a network-traffic predictor.
2. Removing `bwd_URG_flag_count`, which was constant in the supplied data.
3. Identifying repeated input-feature combinations associated with conflicting target labels. The six conflicting groups (128 records) were excluded from the primary modelling dataset rather than assigning an arbitrary label.
4. Retaining the remaining 82 input features: 80 numerical and 2 categorical features, with `Attack_type` as the target.

After the conflicting groups were excluded, the modelling dataset contained **122,989 records**.

### Train/test split

A group-aware stratified split was used so that repeated input-feature groups would not be shared between training and test sets. The first split from `StratifiedGroupKFold` was used, with `n_splits=5`, `shuffle=True`, and `random_state=42`.

| Split | Records | Approximate share |
|---|---:|---:|
| Training | 98,428 | 80.03% |
| Test | 24,561 | 19.97% |
| **Total** | **122,989** | **100%** |

All 12 target classes were represented in both splits. The held-out labelled test data is supplied as `test_data.csv` for the Streamlit application.

**Evaluation note:** Exploratory data analysis was performed on the complete dataset before the split. Model preprocessing and fitting were performed using the training data; the held-out test set was used for final evaluation and was not used for model tuning.

## 3. Models used

All five models were trained on the same training split and evaluated on the same held-out test split.

1. **Logistic Regression** – `max_iter=1000`, `solver='lbfgs'`, `random_state=42`.
2. **Decision Tree Classifier** – `random_state=42`.
3. **K-Nearest Neighbors (KNN)** – `n_neighbors=5`, `weights='distance'`, Euclidean distance.
4. **Gaussian Naive Bayes** – Gaussian Naive Bayes classifier.
5. **Support Vector Machine (SVM)** – a linear hinge-loss classifier implemented with `SGDClassifier` (`loss='hinge'`, L2 penalty, `alpha=0.0001`, `max_iter=2000`, `tol=0.001`, `average=True`, `random_state=42`). This was used as the practical linear SVM implementation for this dataset.

### Preprocessing

The saved model files are complete scikit-learn pipelines. Numerical features are scaled using `StandardScaler`; categorical features are one-hot encoded using `OneHotEncoder(handle_unknown='ignore', sparse_output=False)`. A `ColumnTransformer` applies the appropriate transformation to each feature type before the classifier. The application loads these saved pipelines and does not fit or retrain a model on an uploaded test CSV.

## 4. Model comparison

The following values are from `results/model_comparison.csv` generated by the notebook. Accuracy, AUC, Precision, Recall, and F1 are shown as percentages. Precision, Recall, F1, and AUC are macro-averaged; MCC is shown on its -1 to +1 scale.

| ML model | Accuracy | AUC (macro OvR) | Precision (macro) | Recall (macro) | F1 (macro) | MCC |
|---|---:|---:|---:|---:|---:|---:|
| Logistic Regression | 99.21% | **98.67%** | 97.12% | 93.28% | 95.03% | 0.9802 |
| Decision Tree | **99.80%** | 98.20% | **99.08%** | 96.41% | **97.63%** | **0.9949** |
| KNN | 99.74% | 98.45% | 98.57% | **96.44%** | 97.39% | 0.9935 |
| Gaussian Naive Bayes | 90.07% | 97.73% | 63.32% | 78.59% | 58.89% | 0.7593 |
| Support Vector Machine | 98.22% | 98.01% | 79.42% | 73.78% | 75.74% | 0.9553 |

For the SVM, the macro one-vs-rest AUC was calculated from its class-specific decision scores.

### Observations on model performance

| ML model | Observation |
|---|---|
| Logistic Regression | Produced strong and balanced results, with the highest macro AUC (98.67%). Its macro recall and F1 were lower than those of the Decision Tree and KNN. |
| Decision Tree | Achieved the highest accuracy (99.80%), macro precision (99.08%), macro F1 (97.63%), and MCC (0.9949). Its training accuracy and F1 reached 1.0, while test accuracy was 0.9980; the small train/test gap is worth keeping in mind when considering overfitting. |
| KNN | Also performed strongly. It achieved the highest macro recall (96.44%), narrowly above the Decision Tree, and a macro F1 of 97.39%. |
| Gaussian Naive Bayes | Had the lowest accuracy and macro precision/recall/F1 of the five models. The feature distributions, class imbalance, and relationships between features may not fit the model's conditional-independence and Gaussian assumptions particularly well. |
| Support Vector Machine | Achieved 98.22% accuracy, but its macro recall (73.78%) and macro F1 (75.74%) were lower than the leading models. It did not identify some of the rare classes in the test set, so its overall accuracy does not reflect its weaker performance on those classes. |

### Overall winner

**Decision Tree Classifier** is the overall winner for this experiment based on its highest test accuracy, macro precision, macro F1, and MCC. KNN had the highest macro recall, while Logistic Regression had the highest macro AUC. The Decision Tree is selected as the best overall baseline for this dataset using the reported test metrics.

The dataset is class-imbalanced, so macro-averaged metrics and class-wise reports are important alongside accuracy. The results are baseline comparisons on one held-out split and should not be interpreted as proof that the selected model will generalise identically to every new IoT environment.

## 5. Streamlit application

The Streamlit application (`app.py`) demonstrates the saved classifiers.

Features include:

- Upload a labelled CSV containing the required input features and the `Attack_type` target column.
- Select one of the five saved models.
- View the model comparison and the six evaluation metrics: Accuracy, AUC, Precision, Recall, F1, and MCC.
- Inspect a confusion matrix and classification report for the selected model.

The app loads the saved `.joblib` pipelines. It evaluates the uploaded labelled test data without retraining the models.

### Run locally

Use a Python environment with the dependencies in `requirements.txt` installed, then run:

```bash
python -m pip install -r requirements.txt
python -m streamlit run app.py
```
